# 语义分类参考（给 Agent 用）

脚本**不做**关键词自动分类。你根据每个 skill 的 `description` 语义，归入下列类目之一。

类目可按本机实际技能微调，但不要每次发明全新类目；拿不准就进「其他工具」。

| 类目 | 语义边界（何时归入） |
| --- | --- |
| 文档办公 | 读写/生成 Office 与 PDF、OCR、幻灯片制作 |
| 设计创意 | UI/视觉设计、品牌、主题、生成艺术、图片生成 |
| 图表可视化 | 架构图、流程图、思维导图、Draw.io/Mermaid 等 |
| 浏览器与测试 | 浏览器自动化、页面交互、Web UI 测试 |
| 内容媒体 | 视频/音频抓取、转写、字幕、音视频总结 |
| 写作与沟通 | 润色去 AI 味、对内沟通文案、文档共创 |
| 开发工程 | API/MCP、部署、代码分析、工程脚手架、SDK |
| 代码审查 | PR/代码质量/安全审查（偏 review） |
| Git 与协作流 | 提交、分支、拆 PR、仓库托管相关 |
| 调试排错 | 定位 bug、CI 失败、运行时排查 |
| 前端开发 | 偏前端实现/性能/组件（非纯视觉设计） |
| 后端 / DevOps | 服务端、容器、K8s、CI/CD、运维 |
| Prompt / 工作流 | 规则、钩子、自动化循环、Agent 工作流编排 |
| 协作知识 | 知识库阅读、团队文档检索 |
| 技能元工具 | 查找/创建/安装/管理 skills 本身 |
| Cursor / IDE | Cursor 设置、内置能力、编辑器相关 |
| 其他工具 | 以上都不贴切 |

## 归类原则

1. **看用途语义，不看英文单词是否命中**（例如 description 里提到 `.pdf` 但核心是「做海报设计」→ 设计创意，不是文档办公）
2. 一个 skill 只归一类；有多重能力时选**主用途**
3. 名称仅作辅助，以 description 为准

## 中文说明写法

- 1–2 句，国内程序员口语：说清「干什么」+「什么时候用」
- 拒绝机翻腔（避免「该技能旨在提供…」「利用先进的…」）
- 专有名词可保留英文：PDF、MCP、PPT、OCR、PR
- 无 description → 中文栏写 **【无描述】**
- 原文已是通顺中文 → 可精简润色后放入中文栏，原始栏仍放原文
